# Standalone global file ownership API checkpoint

Small compilable boundary for the reviewed standalone codec design. The complete canonical encoder/reader is the next step; this commit does not yet write or decode global scene bodies. It introduces bounded structural descriptions and a file-owner lifetime which can be tested independently while the closed G2/source bridge is implemented.

`WorldGlobalSceneWriter.StructuralRead` extends the reviewed scalar Mesh (counts/groups/batches/vertex/index) with immutable Description, imageBytes and imageByte. Description owns bounded indexed snapshots of sources<=28/materials<=24/images<=18 and computes the reviewed structural recipe digest; neither its construction nor a hash grants Source authority. No backing arrays, NIO buffers, Image or service handles cross this boundary. The future fixed writer must validate counts/description/pixel products and current scope before any file creation and consume only the synchronous guarded G2 borrow.

`Writer.write(Destination, StructuralRead, stopping)` is a structural compilation/testing interface. Production application wiring must use the fixed canonical implementation once reviewed; it is not a generic public Source promoter. Application Source qualification still requires actual G2 reconsumption, writing before final ALL/Map/WDT/cancellation gates, source-owned unreturned-R cleanup and the accepted post-final resource callback. The interface alone cannot produce a positive source result.

Destination.create takes the application's already-owned private directory, an exact literal Object request identity and scope SHA. It validates normalized absolute default-filesystem paths, derives the literal global.wgs target, generates a random128-bit nonce and performs no directory creation/adoption. The application retains directory ownership. Request identity is compared by `==`, never caller equals/hash methods. ExpectedFile retains full identity/length/counts/recipe/native-wire for parent READY matching; its explicit child InputExpectation subset is identity+length. These are descriptive values, never file/source ownership capabilities.

UnadvertisedFile has a private constructor. The package-internal finalizedCreated handoff requires that the fixed writer already owns successful CREATE_NEW of that exact file; checks alone never grant creation ownership and a failure leaves cleanup with the writer. It checks expected nonce/scope and actual NOFOLLOW regular-file size before creating the owner. There is no public arbitrary path-adoption constructor. Authored tests call this helper only after their own actual CREATE_NEW; those modeled files are ownership fixtures, not codec/source positives.

One-shot move transfers to a separate private-constructed MovedInput; the old source shell becomes inert before return and cannot delete it. Transport verifies `MovedInput.isFor(destination)` and alone deletes after input consumption or actual process drain. Both states use a private internal monitor. File deletion, executor invocation and future completion occur outside it. All allocations required by the ownership transition precede clearing the previous owner. closeAsync validates the existing executor before claiming cleanup; it creates no thread/lane. Returned futures are copies. Cleanup failure is sticky and never reschedules/reports successful retirement. Error terminalizes the private future with a bounded detached class-only IOException before rethrowing the SAME original Error. No foreign getMessage/getCause is invoked or retained. Synchronous close is off-FX only.

Four authored tests cover actual CREATE_NEW/MOVE/inert-shell deletion ownership; literal request identity; canceled close-copy vs held actual deletion; null executor before claim; fatal executor with hostile getMessage and sticky repeated close; and24 concurrent close/MOVE orderings with exactly one deletion owner. No game assets/native/GUI/source capability are involved.

Next: fixed bounded header+descriptor/body writer and reader, CREATE_NEW+NOFOLLOW and exact same-handle length/EOF/hash/CRC validation before positive decoded transfer. The reader will accept the explicit child expectation and validate complete canonical header/descriptor fields before arrays. Existing pure integrity helpers do not replace that validation. Native/GUI enablement remains ungranted.
