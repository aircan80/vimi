# Cold BASIC WMO native pass checkpoint

Work in progress: source code and three offline shader profiles are ready; DX11 generation, independent native pixel/depth/ownership acceptance and cold application integration are still pending. No visible-building release claim. The approved source and structural codec retain their existing caps.

`BgfxWorldWmoPass.readBound(path, actualBaseDecoded, canceled)` invokes the approved annex reader against the actual consumed base before native allocation. The constructor is private, accepts no public neutral DTO, stores the same base origin, and exposes no source certificate. This enforces structural base/payload pairing; game-source authority remains the private source factory. A trusted cold-world owner may attempt at most one WMO pass in its context; failed/closed upload copies and GPU destruction remain charged until its actual context/resource drain. No retry/replacement allocation is authorized just because close issued destruction. A future owner/GUI integration must enforce that reservation and actual drain.

The pass owns one32-byte-stride vertex buffer, unsigned16 index buffer, at most six RGBA8 single-mip textures and dedicated shader/program/uniform handles. Maximum mesh19456bytes; pixels1572864bytes; mesh staging19456bytes; one texture staging262144bytes. CPU decoded payload stays in its original privately owned arrays; upload serializes one bounded direct staging owner and frees it in finally. Issued-copy byte totals deliberately remain charged after close, rather than mislabeling enqueued destruction as real GPU retirement. Native resource failure/cancellation issues destruction of every created handle and clears heap payload aliases; the enclosing owner still owes real GPU/context drain before replacement.

Draw uses only view0 submit/state/uniform/buffer/texture calls after terrain on its existing SEQUENTIAL view. It never initializes a context, creates/sets a render target, sets view clear/rect/mode, clears depth or computes another camera. It uses the SAME TerrainCamera eye/projection functions and original base origin. Fixed model/rotation-only normal matrices are cached once and submitted as u_wmoModel/u_wmoNormal; eye/projection use dedicated u_wmoEye/u_wmoProjection, sampler s_wmoDiffuse. State writes RGB/A/Z with reversed GREATER, no culling/blend/alpha test. Sampler is repeat U/V, linear min/mag and point mip selection over one physical mip.

Dedicated `world-wmo` shaders preserve recorded local positions/UV/normals and the approved double-built model matrix. Fragment lighting normalizes the interpolated native normal only when squared length>1e-12; otherwise diffuse0/ambient-only1/3. The fixed light/floor arithmetic and WMO_FRAGMENT_DEPTH_FOG_V1 use actual perspective-correct eye depth, discard beyond2200 and retain hardware near0.5. No face-normal fallback/backface normal reversal/source lighting colors/client-fidelity claim. Terrain's separate flat maximum-original-triangle fog remains unchanged.

The source compiler wrapper reuses pinned bgfx156/LWJGL3.4.3 tools/includes and writes only its own manifest/resources. Initial Linux-generated GLSL/SPIR-V/Metal blobs are offline source/tool hashed. DX11 must be generated by the pinned Windows workflow; do not fabricate or copy another recipe's blob. Individual native shader reads are capped16KiB to fit the existing metadata/shader reserve. Build/workflow/runtime-probe changes are a separate reviewable commit and must verify all five required recipes/40blobs while preserving existing legacy24+hot8 resources.

Portable compile, Checkstyle and compiler-wrapper tests pass at this checkpoint; this is not GPU acceptance.
