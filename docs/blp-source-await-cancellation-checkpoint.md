# BLP source-await cancellation checkpoint

A synchronous decode could acquire an immediate `AssetSource.bytes` read after cancellation, receive its failed future containing an original clean JDK CancellationException, and have JDK25 `join` manufacture another CancellationException with the original as cause. The strict World source boundary correctly rejected that dirty-looking synthetic outcome. This was observable inside the actual synchronous decoder stack; no arbitrary provider or source-cancellation policy change is needed.

The private BLP read helper now captures the stored outcome through `handle` before joining. It preserves existing CompletionException objects; otherwise it adds one standard fixed-message CompletionException around the original stored failure. It never constructs a message from provider text or calls a foreign exception accessor. This is the same trusted-future preservation principle as the reviewed World source await helper. It does not cancel a source or certify arbitrary asynchronous source IO retirement.

Read EOF classification still maps a direct EOFException or clean standard CompletionException chain containing EOFException to BLP_INVALID. The classifier is bounded to8 exact standard wrappers, rejects auxiliary suppressed failures, and does not traverse foreign subclass accessors or arbitrary causes such as cancellation causes. Dirty cancellation and unknown failures preserve their original identity/cause and remain fatal at the World boundary. The async decoder entry, algorithm, limits, profile, byte ownership and default selection are unchanged; this modifies only the shared read await and its EOF catch classification.

Three authored fixtures cover an actual decodeCore `AssetSource.bytes` read gated until cancellation (original outcome identity, rather than a synthesized cancellation cause); dirty cancellation/existing completion identity/foreign cancellation and completion getter traps; and direct/standard-wrapped EOF classification. The gated fixture fails against the original direct join. No production observer hook or game assets were added.

Validation: `:formats-assets:check`, including integration and interop checks, passes. Private logs `<scratch>/blp-owned-await-causal.log` and `blp-owned-await-check.log`. The owning global source payload uses this decoder synchronously with immediate bytes only; its operation still owns/drains all raw/source/payload resources separately.

Independent review exposed a terminal-EOF classification gap: an EOFException carrying a suppressed cleanup failure still became BLP_INVALID. The separate follow-up qualifies only an exact standard EOFException with null cause and no suppressed failures, after the existing bounded clean standard completion wrappers. Foreign EOF subclasses remain fatal without calling their getters. The causal suppressed-EOF fixture failed before this correction; suppressed/cause/foreign-getter negatives now preserve the original failure, while existing direct/wrapped clean EOF fixtures retain BLP_INVALID. Focused decoder tests plus formatting/Checkstyle passed; log `<scratch>/blp-clean-eof-followup.log`.
