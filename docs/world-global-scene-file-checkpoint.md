# Canonical standalone global file IO checkpoint

Builds on reviewed pure primitives a5405c6 and ownership API f62fafc. This implements `WorldGlobalSceneWriter.writeUnadvertised` and `GpuGlobalWmoSceneFile.read` with shared package-private canonical metadata and bounded IO helpers. No Source/public facade, MOVE application bridge, native renderer/shader/context, status emission or GUI enablement is added. File validity remains structural; only the closed actual G2 source operation can qualify an application result.

## Fixed writer

The writer captures bounded immutable description/count/group/batch metadata, validates source/material/image products, computes native group/mesh hashes and exact native bounds, and validates destination scope before creating any file. Its only output is the literal default-filesystem normalized absolute `global.wgs` destination. The already-owned parent directory must be a NOFOLLOW directory. Actual file creation uses CREATE_NEW+READ+WRITE+NOFOLLOW; a failed CREATE_NEW never claims cleanup of a preexisting file.

Header1024 and descriptors<=6016B follow the reviewed exact offsets, little-endian fields, roles, counts and reserved zeros. Native vertex/index and each image stream into one64KiB body buffer, with one4KiB image scratch. Every output image byte is bounded, alpha255 and checked against its exact opaque SHA. A separate bounded positional cache rereads the actually written mesh on the SAME handle, recomputing group/native hashes AND actual native bounds; mutable structural borrows cannot silently substitute other geometry after preflight. There is no full-reader/CPU-payload construction in the parent writer.

After the body closes logically, actual bodyCRC is filled; masked headerCRC is filled; actual whole-file SHA/bodyCRC are computed on the same read/write handle with a64KiB buffer; the whole-SHA hole is filled. Actual EOF/size and integrity are checked before the channel closes. Only then is the private UnadvertisedFile returned. Until an R is returned, the writer itself owns every successful CREATE_NEW. All IOException/RuntimeException/Error paths attempt deletion of only that owned path, preserve the original failure and attach any distinct cleanup failure; no exception is converted to a Source refusal or a positive output.

## Same-handle reader and private payload

The reader checks default normalized absolute input and NOFOLLOW regular-file size, then opens exactly one READ+NOFOLLOW channel. Header magic/version/header size, expected nonce/scope/stored SHA, profile/mode/transform, canonical counts/offset products, raw identity/MODF zero profile, positive-zero origin/bounds, reserved bytes/unused image slots and headerCRC are validated with fixed small allocations.

A complete first same-handle SHA/CRC/EOF pass precedes large CPU payload arrays. Only after that integrity gate does the reader parse bounded descriptors, cross-check source order/uniqueness/length/role, material/image references and first-use slots, group/index/batch partitions/spans, image extents/stat tuples and recomputed recipe. It uses a second cursor over the SAME channel, comparing the actual second header AND descriptor bytes to the pinned metadata, decoding and hashing again, validating finite/canonical XYZ/UV, group-global uint16 indices, every opaque image/hash, exact native bounds and all group/native-wire hashes. Exact terminalEOF/final handle size and final expected whole SHA are required again before transfer. Thus neither a second path open nor a checksum-before-copy time gap can mint a positive decoded result.

Decoded has a private ownership-taking constructor, one float XYZUV array and one expanded int index array, and at most18 actual RGBA arrays. Scalar reads are checked under its private lock; no mutable array, NIO, Image or public ownership-taking constructor escapes. Close actually detaches payloads; descriptive metadata remains historical. Partial allocations are method-local and no decoded owner escapes a failing hash, cancellation or channel-close path. There is no cache or asynchronous decoder worker.

These allocations preserve the approved component envelopes. The parent writer never owns another full mesh/image/file mirror: bounded metadata, two4KiB digest feeds,64KiB sink/image/cache/hash phases and incidental bounded default-JDK heap-IO staging fit its already reserved1MiB writer/scratch phase. The writer releases its application-owned heap scratch before Source final native Map work; returned R retains only path/request identity and fixed descriptive expectations. This does not imply GC or immediate retirement of JDK native staging. Sequential, non-vectored default FileChannel heap-buffer IO can cache its temporary direct buffer on the same worker after the channel closes. The largest writer IO buffer is65536B. Charge a conservative262144B persistent staging allowance through the final Map phase, rather than assuming that cache is emptied:15990784+262144=16252928B, below the unchanged16777216B component ceiling by524288B. This allowance accounts for staging attributable to this bounded writer; unrelated worker/JVM caches remain outside this component claim. No extra payload, source graph or file mirror is retained. Child CPU mesh remains<=1048576B and RGBA<=4718592B; file/cursor buffers are64KiB and digest scratch4KiB, with small headers/descriptors and bounded default-JDK IO staging charged to the approved file/codec/reserve rows. This is a logical component accounting statement, not a whole-process RSS or native allocation proof.

## Pinned JDK staging observation

On the pinned Adoptium25.0.5+8-LTS runtime, a private diagnostic performs sequential heap-buffer FileChannel writes/reads (65536B maximum, then1024/6016/65536/1B reads), closes the actual channel, and inspects only the current thread temporary-buffer cache. It observes one cached direct buffer of65536B after close. Local `javap -c -p` inspection of OpenJDK25 `sun.nio.ch.IOUtil`/`Util` confirms heap IO obtains a temporary direct buffer and returns it to `Util.bufferCache` (`TerminatingThreadLocal`) rather than necessarily freeing it. The codec uses neither gathering/scattering IO nor nested channel calls, so it does not request multiple simultaneously borrowed staging buffers. The262144B allowance above is conservative for this fixed sequential pattern; it is not a portable guarantee that arbitrary FileChannel workloads or preexisting caches have that size. Diagnostic source/log remain private: `<scratch>/GlobalFileStagingProbe.java` and `global-file-staging-probe.log`. No production IO or admission limit changes are needed.
