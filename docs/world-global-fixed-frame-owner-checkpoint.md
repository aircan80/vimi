# Private fixed global frame owner

Implements the approved4825e40 frame-owner scope only. `GlobalWmoFrameOwner.allocate(mapping)` returns a shell with no direct/native allocations; register it before fallible `initialize(Decoded,cancellation)`. The first accepted initialization adopts Decoded, including failure paths. Repeated initialization/foreign-thread calls are rejected before adoption. No constructor can strand an allocated destination. The mapping is caller-owned and must be exactly800×500.

The enclosing native owner calls `close()` in finally, then actually shuts down its context, then calls `afterContextShutdown()` ONLY after shutdown returned successfully. Close stops submission, polls actual readbacks for at most5s with modular uint32 readiness, attempts all native handle/Decoded cleanup and always retains direct destinations. Neither successful resource destruction nor timeout authorizes early destination free. `afterContextShutdown` is a private trusted-owner operation, not a receipt manufactured by this class. Unknown shutdown failure must retain destinations/process ownership; production child integration remains separate.

Three fixed800×500 readback textures/direct destinations, one color/depth target pair and one reusable packing buffer implement the approved19,200,256B frame-owner ledger (including borrowed4,800,256B mapping) within41,154,816B standalone logical envelope. Direct payload remains6,400,000B throughout all viewport sizes, including normal close until shutdown. No per-frame pixel array or resize target allocation is made by the owner. RendererCPU/GPU/queued-copy ownership stays charged separately within the existing envelope. Small request/ByteBuffer view objects are bounded transient metadata, not pixel owners.

Each slot captures the exact immutable GlobalWmoFrameRequest(revision,camera,width,height). Requests are positive and strictly increasing when issued, dimensions1..800×1..500, camera uses existing separate global bounds/origin0. One draw per bgfx frame; advance resets admission, waits actual modular fences, publishes only newest ready revision and releases all actually ready slots. Frame sequence exhaustion fails closed. This immutable-scene owner has no terrain content transactions, statuses, CLI parser, process, source service, global context claim or application arbiter. It never autonomously draws an initial camera.

Physical800-pixel readback stride is always respected. Requested rows are packed into the one reusable buffer before GpuFrameFile.write. Origin-bottom-left addressing uses physicalHEIGHT−1−row, independently covered by a pure asymmetric packing test; actual hardware proof here is Vulkan only, not Metal/GL orientation qualification.

Validation: fullrendering-bgfx:check plus actualnativeGpuGlobalFrameOwnerProof passes. Three pure tests cover modular wrap, both row origins/317×163 stride, request and shell lifecycle bounds. Authored actual Vulkan proof renders12 camera/size frames (800×500,317×163,160×80) with48 independent ray/plane UV/bilinear pixel comparisons, then pipelines3 outstanding readbacks with exact finalrevision15/dimensions255×129. Direct payload remains6,400,000B (about6.10MiB). Two separate partial-initialization contexts cancel/throw the SAME authored Error after one1.6MB destination is registered; close retains it until actual shutdown and finaldirectbytes0. All original candidate/production shader resources are unchanged. Log HOMEtmp/global-fixed-frame-final.log; proof output is generated/private.

Limitations: the timeout branch and failing native shutdown are not hardware-injected; these remain integration fault-injection gates. Pipelined proof establishes three outstanding slots and latest ticket metadata, not independent publication of every superseded ticket. No blocked pipe, process exit, Source-to-file authority, JavaFX acceptance, Windows hardware or universal performance claim follows. Existing preview arbiter and closed source writer/MOVE must be integrated and reviewed separately before application enablement. CandidateDX11 remains pending in this branch; test-only six candidate blobs are not promoted to production distribution.
