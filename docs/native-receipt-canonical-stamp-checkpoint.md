# Bounded detached native receipt stamps

Pure formats-table identity support for the approved single-root liquid inspection design. `NativeIdReceiptFingerprint.canonicalStamp(receipt)` uses the **same canonical v1 serializer and preallocation metadata guards** as existing `sha256(receipt)`. The original SHA path still streams directly to its digest and retains no serialization buffer. Both paths reject mismatching actual-column identity. No source IO, native witness, positive constructor, table membership or qualification capability is added.

`CanonicalStamp` has a private constructor, one private immutable byte array, exact byte equality/hashCode and only an encoded-length accessor. It retains no receipt/schema/row/source handle and exposes no array/buffer getter. Caller-forged descriptive receipts can yield descriptive stamps; successful encoding is never native authority. The source factory must independently qualify actual native captures and compare full stamps from fresh captures before positive transfer.

Canonical encoding has a hard128KiB bound. The output starts at512B and grows geometrically **clamped to128KiB**, checking required size before growth/copy. The final exact-sized immutable array is detached; construction temporarily owns old/new growth arrays or output+trimmed array (≤256KiB), separately charged in row identity scratch. A retained stamp is≤128KiB plus fixed metadata. Two liquid table stamps therefore require up to256KiB before their other tuple/anchor/control facts; the liquid design control reserve will increase from256 to512KiB by consuming256KiB of its existing headroom, preserving the proposed8MiB component ceiling. This checkpoint changes no runtime component cap or source integration.
