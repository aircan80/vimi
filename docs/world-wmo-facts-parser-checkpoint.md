# WMO17 raw facts parser checkpoint

Status: raw parser/API for independent review. No source service, positive renderable factory, asset resolution, placement transform, material admission or renderer change. The city and instance source checkpoints remain descriptive evidence rather than appearance approval.

`formats-world/WmoFormats` adds source-byte-array entry points `root` and `group`, with explicit `Limits`, a cancellation predicate, and revision`wmo17-facts-v1`. Callers own source acquisition/authentication and keep input stable during parsing. Parsed facts retain no source-array alias. Geometry/texture-name bytes use private owned arrays and read-only views; no public constructor can smuggle mutable geometry into a positive asset. These are raw facts, not renderable assets.

Root parsing checks exactly one MVER17/MOHD64/MOMT declaration, header/material count agreement, unsigned fields, finite/ordered source bounds, bounded raw MOMT16-word declarations, optional GFID and optional bounded MOTX bytes. GFID preserves flat source order, unsigned zero/high IDs and presence separately from an absent inventory. It does not infer LOD dimensions, resolve legacy group names, or invent filenames. MOMT reference operands remain explicitly UNRESOLVED_UNSIGNED32; actual file-ID/name-offset semantics belong to a source-qualified profile.

Group parsing checks exactly one MVER17/MOGP, the68-byte header and exact nested chunk boundaries, MOVT/MONR/MOVI/MOBA/MOPY singletons, bounded repeated MOTV streams, finite values, normal/UV shape, index ranges, batch count agreement, triangle-aligned index spans and inclusive per-batch vertex ranges. Raw MOBA bounds words/flags/materialByte, padding/tail fields and MOPY flag/material bytes remain uninterpreted; alternate material-index flags are not guessed or rejected as ordinary byte indices. No collision-only triangle filter is applied. No UV, normal or coordinate conversion occurs.

Every declaration has a bounded tag/byte-count descriptor and `payloadParsed` flag. MOCV, MLIQ, portal/light/doodad data and unknown tags remain explicitly **unparsed**; their presence cannot become an empty/fully supported appearance. Their bodies are not retained by this slice. A later consumer must explicitly qualify or reject them. Missing required geometry declarations fail parsing; explicitly recorded zero-length geometry is a valid distinct fact result. Missing GFID is preserved as missing, not a complete empty direct-reference inventory.

## Fixed limits and named owners

Standard ceilings:8MiB per root/group input,1,024total chunk descriptors per source,256root groups,256materials,4,096flat GFID entries,65,536vertices,131,072triangles,256batches,4UV streams,64KiB MOTX bytes and12MiB logical retained-fact charge. The one-asset shape preset narrows to1KiB root/32KiB group,1group/1GFID entry,6MOMT records,512vertices/512triangles,6batches/1UV stream and256KiB logical facts. It does not authorize six actual images: image-domain resolution/count/pixel limits are a later factory gate. Additional nonzero texture operands remain raw facts rather than silently discarded references.

Count/stride/source interval and logical-byte checks happen before array allocation or element decode. Budget charges cover fixed builders, primitive arrays, material/batch/list copies and chunk descriptors. Source bytes are caller-owned and separate from the fact charge; metadata/allocator/JVM/driver overhead is not a claimed RSS cap. The private parser transfers its owned arrays into results rather than cloning all geometry at publication. Batch index inspection has a separate ceiling of3×the configured triangle limit, preventing repeated overlapping batches from multiplying validation work without bound. Limit exhaustion refuses the source; no truncated geometry or biased positive result is returned.
