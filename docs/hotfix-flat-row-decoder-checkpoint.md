# Bounded flat hotfix row decoder

First decoder-only slice frommain74322493. No cache state/winner selection, key bootstrap, effective-table activation, generated artifact mutation or native capture/certificate change. It consumes caller-owned immutable/pinned payload bytes; container `readPayload` must separately bind the selected physical entry/body to the actual imported snapshot. A decoded row is HOTFIX-derived data, never VERIFIED_NATIVE evidence.

## Contract and reference

`HotfixRowDecoder.Layout(schema,nativeHeader,nativeFlags,nativeIdFieldIndex)` carries explicit structural context. The existing public Db2Types.Header omits raw ID flags/index, so callers must supply them from the SAME actual native header/qualified binding; this record itself grants no Source authority. Decoder checks entry tableHashu32 against native tableHash, nativeWDC3/4/5 layout against the selected DBD layout list, flattened column names/kinds/isID against schema, and actual flags bit4/noninline-ID plus logical idIndex (orFFFF for noninline). Unknown raw-physical integer interpretations are declined, not coerced into candidate DBD types.

Pinned [DBCD HTFXRow.GetFields](https://github.com/wowdev/DBCD/blob/2180edb4d08b3822b3cfa964293ba8ccd4236ac0/DBCD.IO/Readers/HTFXReader.cs) reads logical definition order using byte-aligned primitive readers and inline zero-terminated strings. The noninline ID consumes no payload; noninline relation values DO consume payload in definition order. Its [builder](https://github.com/wowdev/DBCD/blob/2180edb4d08b3822b3cfa964293ba8ccd4236ac0/DBCD/DBCDBuilder.cs) maps declared integer widths8/16/32/64 and float32; localized strings are one string for these modern formats. We reuse neither native WDC physical compression/palettes nor native string offsets/relationship side blocks. This Java profile intentionally refuses unconsumed tails instead of inheriting the reference's permissive auxiliary-data behavior. A future auxiliary profile needs its own exact table/layout evidence.

Public synchronous `decode(Layout,entryTableHashU32,recordIdU32,ByteBuffer,Limits,Cancellation)` returns `Decoded(row,consumedBytes)`. Noninline ID is the external uint32 ID; inline ID bits must equal it. Signed integer cells retain signed values, uint64 retains its full decimal domain, float cells use native-reader-compatible Float.toString including signedzero. Arrays flatten in DBD order; UTF8 Cstrings require REPORT decoding, terminator and string bound. Input slice positions stay caller-owned. Row is a full replacement (isCopyfalse), not a native copy record. Invalid messages and Decoded.toString contain no payload/cells, including potential key material.

## Bounds and ownership

Hard maximums: payload65536B,512 logical/flattened columns (raised from128 to the base DB2 reader's own flattened-column bound; PlayerCondition has224), string16384B, aggregate output131072UTF16 units, at most64 selected-layout names; caller Limits can narrow but cannot raise these. Counts/row length/schema shape are checked before row-value construction, every scalar has an exact input bound, cancellation is checked before decode/each field/sample and while scanning strings, and terminal EOF is mandatory. Returned values are immutable and hold no schema, source, table service, raw payload, buffer alias or native witness. A conservative standalone logical decode allowance is512KiB: bounded caller-owned64KiB input, at most256KiB output characters plus bounded list/scalar metadata and one<=16KiB UTF8 input view/<=32KiB decoder character scratch. This is not an effective-table-wide budget or whole-process RSS claim; root overlay owns snapshot/row aggregation limits separately. No worker, direct/native allocation or IO is introduced.

Seven authored tests cover all signed/unsigned widths, actual LE values, noninline ID, inline mismatch, uint32 IDs, included noninline relation, arrays, selected-locale text/strictUTF8, exact truncation/tails, limits/cancel and layout/storage/column refusal. A genuine authored bitpacked12-bit native DB2 record (reader-produced Header) is contrasted with its one-byte DBD8 hotfix payload; using native compressed width would fail this oracle. No real cache/key payload appears in fixtures or Git. Full formats-tables check passed before the final added unsupported-width/raw-interpretation fixture; focused final tests/style are recorded separately in review evidence. Effective view/query/relation/capture separation and matching70707 import remain the coordinator's separate next slice.

Raw-physical columns (decoder revision v3): a header column that base rows keep as its raw physical integer is decoded at its declared width only when it is an unverified-name, non-relation field whose interpretation describes exactly that width and signedness, and every base value of the column fits it (non-negative and below the declared range). Only a READY base qualifies, scanned completely and unchanged during the scan; PARTIAL tables (encrypted or missing sections), tables over the scan bound, non-OK or failing pages stay refused. Because actual values are checked, every storage kind (including 0 and 1) can qualify. A completed scan is cached per base identity and survives view eviction; an inconclusive or failed scan is never cached, and the view is rebuilt with a fresh scan after a back-off (5 s doubling to 5 min, counted per base identity). After 8 inconclusive scans of one base the raw columns stay refused without further scans until the base changes or the handle is reopened. The previous view stays in use until its rebuild is accepted, so a refused rebuild keeps the working overlay, and a view already used in an operation is never rebuilt within it. Closing and cancellation propagate rather than counting as an unreadable base. Raw-evidence and low-bit-collision columns, values that do not fit (for example a float stored where a u16 is declared) and negative decoded values stay refused. On the Forever 70790 cache this decodes 6 READY tables whose replaced rows all match base (TraitEdge with its 12 prerequisite edges, CooldownSetSpell, ChrCustomizationChoice, SpellVisualEffectName, SpellVisualMissile, Cfg_GameRules); the PARTIAL CreatureDisplayInfo, SpellAuraRestrictions, SpellReagents and PlayerCondition and the non-fitting CreatureXDisplayInfo stay refused.

Optional key data (decoder revision v6): a body followed by exactly 28 bytes that start with the TactKey table hash (0xDF2F53CF) is a server optional-data block (hash, 8-byte key name, 16-byte key) such as BroadcastText carries. The row is fully described without it, so the block is stripped (never decoded into the row or exposed) and the row is shown as a hotfix row; hotfixInfo and Source details note that it carried a key not needed to read it. Any other trailing bytes, zero padding included, are refused as TRAILING_BYTES with their count.
