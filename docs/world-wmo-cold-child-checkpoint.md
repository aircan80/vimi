# Optional cold World child building pass

Scoped implementation after approved `0cb036f`. `GpuViewerMain` accepts optional `--wmo-annex <absolute-normalized-private-path>` only with immutable cold `--terrain-scene`; model/headless mixing is rejected and v2 remains unchanged. Actual terrain bytes are decoded/bound once when either annex is requested, then reused for both existing terrain textures and WMO pairing. This adds no source authentication, GUI wiring, hot WMO support, instance mode or view-distance change.

`ColdWorldWmoOwner` spends one attempt and conservative 6,175,744-byte envelope before packet IO/upload. Expected IO/pairing/native initialization refusal emits bounded UNAVAILABLE/LOAD while base terrain continues; cancellation and unexpected failures propagate. Destruction/failed prefixes remain charged after close until the enclosing actual `bgfx_shutdown` returns. The owner cannot retry or reset. Pipeline construction includes the optional attempt in its cleanup scope, including direct readback staging already allocated before that attempt. Rendering submits terrain then optional WMO with identical request camera/dimensions, existing view0, target and readback ring.

The optional six-token `WorldWmoStatus` protocol reports initial/per-image LOADING, complete native INITIALIZED, and READY only at the first actual mapped publication, before generic READY. Failed optional inputs never emit initialized/ready. Counts are bounded 0..6 and startup has at most ten lines. Without the flag there are no WMO status lines. Parent interpretation and user-visible BASIC disclosures remain future integration work.
