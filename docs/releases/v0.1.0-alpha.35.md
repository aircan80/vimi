# VibeMiner v0.1.0-alpha.35

This update draws all of Stormwind City's interiors and the furniture inside
them, and makes the city's objects settle sooner. In alpha.34, 115 of
Stormwind's 280 interior groups were capped; all 280 now draw. Set doodads
inside building interiors are now hidden with their room when the portal walk
does not reach it, and they get their own model allowance, so far fewer are
capped. Doodad models and their skins are now read ahead of the placement walk,
so objects settle faster than in alpha.34. Library storage did not
change: no schema version or table changed since alpha.34, so an alpha.34
library opens as it is, without migration, and no saved binding is rebuilt.
This release covers #648, #649 and #650.

The changes were measured on real data with the World measurement probe on
Classic Era, build 1.60.1.70862, around Stormwind (tile 48,31), and covered by
unit tests. The World object GPU proofs, including the portal-cull proof, pass
on Vulkan on Linux. The owner's on-screen checks on Windows with Direct3D 11
are still pending for this release and for alpha.34 back to alpha.29, and
nothing new was run on Metal; see Known limits at the end.

## Stormwind interiors

- **Their own allowance.** The interior groups of a building drawn by group
  now draw from what its exteriors leave of the large allowance plus a new
  interior allowance of 327,680 vertices, 983,040 indices, 1,024 ranges and 64
  opaque image slots. Their image pixels still come from the tile's building
  pixel budget, after the exterior images (#648).
- **Exteriors first.** Within a tile, exteriors never draw from the interior
  allowance and never give up geometry or slots to an interior: every such
  building's exteriors on the tile are admitted before any interior. Pixels
  are shared, so a split building's exterior images can lose a little
  resolution when its interiors draw (#648).
- **Measured.** Around Stormwind, Stormwind's interior groups drawn went from
  165 to 280, and interior groups capped on all tiles from 124 (115 of them Stormwind's) to 9, none of
  them Stormwind's. At Near, GPU memory went from 230.0 to 245.9 MiB; at Far,
  from 405.1 to 420.9 MiB. The heaviest tile, 48,30, needs 448,746 vertices
  and 1,247,094 indices with every interior drawn (#648).
- **Objects budget.** With every Stormwind interior drawn, the 24 Far object
  sets around the city take 189.7 MiB. The Standard objects budget went from
  192 to 212 MiB, about 12% over that, so an outer-ring tile does not lose its
  objects to the budget. The High budget stays at 256 MiB (#648).

## Furniture inside interiors

- **Hidden with their room.** Each interior group's doodad references (MODR)
  are now read. A set doodad listed by only one group the tile read, when that
  group is an interior, is tied to that group, and is skipped in a frame when its building's portal
  walk ran and did not reach that group. When the building is out of view, the
  doodad keeps its own frustum test. A doodad listed by several groups stays
  untied and draws as before. For a building drawn by group, a doodad is tied
  only to the interior whose box placed it on the tile (#649).
- **Their own model allowance.** Tied set doodads may read up to 128 more
  doodad models beyond the tile's 96, with 160 more image slots. Every other
  doodad keeps the 96-model rule. These models share the doodad vertex, index,
  range and pixel pools, and their images get levels after every other doodad image
  (#649).
- **Measured.** In the 5 x 5 tiles around Stormwind, set doodads drawn went
  from 8,979 to 13,247 and set doodads capped from 5,171 to 717. At Near,
  frame draws went from a mean of 776.5 to 703.6 (p95 1,161 to 989), with
  about 731 tied placements culled per frame. GPU memory went from 245.9 to
  252.8 MiB at Near and to 430.6 MiB at Far (#649).
- **A malformed MODR** loses only its references, never the group, and
  references past the root's doodad list are dropped (#649).

## Faster objects

- **Read ahead.** Doodad models were read one at a time during the placement
  walk, at about 2.8 ms a read. Each doodad pass now queues its doodads first
  and asks the read-ahead for the models it will certainly read: a model's
  first use within the model cap, or the cap plus the allowance for a tied
  doodad, while the placement cap cannot
  be reached. When a model arrives, the read-ahead reads its first skin too.
  Placement then runs in the same order with the same counts (#650).
- **Unchanged output.** The same doodads draw and are capped, and the objects
  files around Stormwind are identical after their per-run header. Read
  budgets are still charged only when a read is used, and a capped model is
  never opened (#650).
- **Measured.** Around Stormwind, objects settle at Near in 15.6 s, down from
  21.3 s with #649 and 18.6 s before it; at Far in 33.6 s, down from 47.4 s and
  39.6 s. Preparing the 5 x 5 tiles takes 20.0 s, down from 34.3 s (#650).

## Storage

Library storage is unchanged: no schema, user version or table changed since
alpha.34, and no saved binding stamp changed, so nothing is rebuilt.

The tile objects file went to version 9, which stores a set doodad's tie to its
interior group in a placement field that was reserved; version 8 is refused.
Those files are written per session, so no saved objects tile outlives the
change (#649). Its per-tile ceiling went from 33 to 46 MiB with the interior
allowance (#648).

## Measurement and tests

- With stage timings on, the renderer counts tied placements culled in a frame,
  `child.frame.portalPlacementsCulled` (#649).
- New tests cover the interior allowance: interiors drawing from what the
  exteriors leave plus the allowance, exteriors never using it, separate image
  slots, two split buildings on one tile, and the objects budget with its
  margin over the measured Far peak (#648).
- New tests cover tied set doodads: reading MODR and its malformed shapes,
  which doodads are tied and which stay untied, the split-building box rule,
  the model allowance and its boundary, the version 9 file round trip and every
  invalid tie the reader refuses, the renderer's cull decision, the bridge
  dropping ties to capped buildings, and a read profile covering every doodad
  image slot read twice. The portal-cull GPU proof gains a tied doodad shown
  when its room is visible and culled when it is not (#649).
- New tests cover the read-ahead: the same output with it on and off, skins
  served from it, models sharing one skin, capped models never opened, and
  cancellation (#650).

## Known limits

- **Interiors in cities are partial.** Outside Stormwind, in the big cities most interior groups
  are read and then capped by the building geometry budget the exteriors
  leave, and counted as `GROUP_INTERIOR_CAPPED`. Undercity's exteriors already
  use 273,669 of its 294,912 building indices. Raising that budget is a
  separate decision. On one Undercity tile, roots whose portal set was dropped
  draw unculled, with only the few interior groups that fit (#641).
- **Tied set doodads.** Culling trusts each group's MODR. A doodad that
  sticks out through a doorway can be hidden while its outside part would be
  in view. A doodad listed by several groups stays untied and draws whenever
  its placement is in view. For a building drawn by group, another tile's
  group could also list a doodad tied here (#649).
- **Set doodads still capped.** In the 5 x 5 tiles around Stormwind, 717 set
  doodads are still capped: untied doodads past the 96-model cap, which the
  interior allowance does not cover (#649).
- **Allowance models.** An untied doodad can reuse a model read through the
  interior allowance, and that model's images are then given levels with the
  other doodad images. On a tile already at its doodad pixel budget, the
  allowance models' images get a low resolution (#649).
- **Doodad images are still read one at a time.** Only models and their skins
  are read ahead; doodad images take most of the remaining read time (#650).
- **Far objects budget.** The 24 Far object sets around Stormwind now take
  about 195 MiB of the 212 MiB Standard budget (#648, #649).
- **Each owning tile walks the whole set.** That is up to 6 walks of 289 groups
  per frame for Stormwind (#644).
- **A second placement of a split building.** A building is decided once per
  tile by its largest placement. A second placement of a building drawn by
  group on the same tile is capped (#643).
- **Instance maps.** On instance maps, a building over the tile's remaining
  group reads is still capped before it is sized, so it is never drawn by
  group (#643).
- **Identical placement records.** The owner rule assumes every tile that
  lists a placement holds an identical MODF record for it; tiles whose records
  differed would pick different owners (#643).
- **Interior lighting.** Interiors are lit from their raw vertex colours, and
  the client's exact formula is not pinned (#474): the alpha term of the
  client's colour adjustment is not applied, and MOHD flags 0x2 and 0x8 are not
  honoured. If the client does add some ambient, interiors can look darker than
  in the client; the two darkest seen in Thunder Bluff are root 113750 group 1
  and root 113146 group 2. Doorway (trans) batches get full interior light,
  with no blend to the sun. A group flagged both exterior and interior is lit as
  interior, where the client may light it as outdoor. There is no sky and ground
  split of the ambient, and the building's own lights are not read. Set doodads
  marked to use interior light (MODD 0x2) are still lit by the sun (#383, #293,
  #646).
- **Exterior image levels.** The reserve for interior images can lower an
  exterior image's level slightly, by at most the smallest level of each
  interior-only image (#641).
- **No switch for interiors.** Interiors are always drawn; no setting turns
  off only interiors. `-Dvimi.world.exteriors=false` still turns off all
  buildings. Only the probe can measure exteriors without interiors (#641).
- **No World creatures on Anniversary.** There is no reviewed source of
  creature spawns for build 2.5.6.70577, so `-Dvimi.world.creatures=true`
  shows no creatures there.
- **Humanoid NPC appearances on Anniversary.** The tables that describe
  humanoid NPC appearances have not been reviewed for that build.
- **Sky rows skipped on Anniversary.** 12 LightData rows are skipped because
  their colour values have a top byte that is set, such as `0xFF242141`, and
  what that byte means on this build is not established. In 10 rows, from two
  parameter sets, the sky colours are unreadable and the whole row is skipped.
  In 2 rows, from two other parameter sets, only the direct and ambient light
  are dropped and the sky and fog are kept (#634).
- **Other layouts.** Only the Anniversary Map, LightParams and LightData
  layouts added in alpha.32 are reviewed. Other classic layouts are refused
  until they are seen and reviewed (#632, #634).

  The Metal shaders are built, and nothing new was run on macOS hardware.
- **Creatures still in the rest pose.** In the previews, billboard bones with
  child bones or rotation keys, members not rigidly bound, lock-X cards and a
  few parent-inheritance flags still refuse the Stand. In the World, 3 models
  with ignore-parent flags and the two models above the bone limit stay in the
  rest pose. Models whose Stand records no bone keys show their rest pose
  (#384).
- **Creatures not drawn in the World.** On Classic Era, 70 of the 1,051 sampled
  census models still have no surface the World can draw, and 2 have
  visibility unresolved. The remaining refusals include 19 character race
  displays with no table naming their skin, which need character composition
  (#385); 3 displays with an empty object skin slot; and 3 whose texture is not
  stored in the measured local copy. Two external-skeleton models are still
  not drawn because of other blockers (#636, #639).
- **Glow and blended parts in the World.** Colour tracks are not applied as
  tints or alpha, so a blended part can draw more opaque than in the client.
  Glows are drawn unlit, so glow batches not marked unlit draw brighter at
  night than in the client. Blended parts sort per part within a creature, so
  overlapping parts can sort wrongly from some angles. A creature shown in its
  rest pose draws its camera-facing glow and blended quads fixed. Fading
  weights are taken at time 0 of Stand, so a glow that pulses or fades during
  Stand stays at that value. On models whose Stand plays from an external
  skeleton, a keyed weight is decided only when every keyed slice starts full,
  the model has no sequences or global sequences of its own, and the track
  uses step or linear keys on sequence time (no global clock); the others are
  still left out, as are
  fading weights on creatures in the rest pose. Weight tracks are not read from
  `.anim` files or a parent skeleton (#361, #623, #625, #628, #636).
- **Bone files** are not applied for character displays, and `.anim` files and
  parent skeletons are not read (#384).
- **Sun direction.** The light's direction is still fixed. The light tables
  record colours, not a direction, and the client's sun path is not pinned yet
  (#177).
- **Water depth.** The shallow-to-deep mix reads the depth byte linearly; the
  client's exact curve and water textures are not used yet (#594).
- **View distance.** Near stays the default; whether Far becomes the default is
  not decided (#173).
- **Opt-in features.** These are Java system properties for testing, not
  settings in the app yet:
  - splat blending: `-Dvimi.world.splat=true`;
  - the recorded sky, fog, light and water light: `-Dvimi.world.sky=recorded`,
    with `-Dvimi.world.sky.time=HH:MM` to pin a time;
  - creatures: `-Dvimi.world.creatures=true`;
  - WMO vertex colours on exteriors: `-Dvimi.world.wmoVertexColours=true`
    (interiors use theirs by default);
  - high object texture detail: `-Dvimi.world.objectTextures=high`;
  - native presentation into a child window, on Windows only:
    `-Dvimi.world.nativePresent=true`.

  `-Dvimi.world.viewDistance=far` still forces the Far view distance. Terrain
  lighting is on and can be turned off with
  `-Dvimi.world.terrainLighting=false`.

- **Linux:** packages need the standard GTK and X11 desktop libraries, and native
  presentation is not available. The deb dependencies added in alpha.29 were
  not tested with a clean install.
