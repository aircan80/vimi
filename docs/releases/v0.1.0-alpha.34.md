# VibeMiner v0.1.0-alpha.34

This update draws Stormwind City. Before, its one building was capped on every
tile that places it, so the city never drew. It is now drawn group by group
across the tiles it covers, each group exactly once over the map, and its
interiors are drawn culled by a portal set built from its root file. Also,
caves and building interiors are now lit from their own baked vertex colours
instead of the World's sun. Library storage did not change: no schema version
or table changed since alpha.33, so an alpha.33 library opens as it is, without
migration, and no saved binding is rebuilt. This release covers #643, #644,
#645 and #646.

The changes were measured on real data with the World measurement probe on
Classic Era, build 1.60.1.70862, and covered by unit tests. The World object
GPU proofs, including the portal-cull and material-class proofs, pass on Vulkan
on Linux. The owner's on-screen checks on Windows with Direct3D 11 are still
pending for this release and for alpha.33, alpha.32, alpha.31, alpha.30 and
alpha.29, and nothing new was run on Metal; see Known limits at the end.

## Stormwind

- **Why it never drew.** Stormwind City is one placement (root 7962574) about
  2,138 yards across, listed by every tile it overlaps (tiles 46 to 49 by 29 to
  32 on map 0). Its 9 exterior groups alone need 150,358 vertices and 322,080
  indices, more than a tile's building pool of 98,304 vertices and 294,912
  indices, and caps never split a building, so every tile capped it (#643).
- **Drawn by group.** A placement is now drawn by group when its recorded
  bounds cross a tile border and its exterior groups, sized alone, are over an
  empty tile's building pool. Every other building is admitted exactly as
  before. Each group belongs to the tile holding the centre of its box from the
  root file (MOGI), placed by the building's rotation and scale. The rule reads
  only the placement and its root, so the tiles agree on every owner without
  seeing each other, and each group is drawn exactly once. A tile does not read
  groups another tile owns (#643).
- **Its own allowance.** The exterior groups a tile owns use a separate large
  allowance, never the tile's building pool: 131,072 vertices, 393,216 indices,
  512 ranges and 64 opaque image slots. Their images get their pixels after the
  tile's own exterior images. A building drawn by group is placed after
  everything else the tile draws, so it never displaces the tile's buildings,
  doodads or interiors (#643).
- **Interiors, portal-culled.** Stormwind's 280 interior groups are drawn on
  the tiles that own them, culled by a portal set built from the root file
  alone: group flags and boxes from MOGI, and each group's portal references
  recovered from the root's reference list (MOPR). Every owning tile carries the
  same whole set of 289 groups and 319 portals, so the renderer's portal walk
  can start in a room another tile draws and pass into this tile's rooms. A
  building's interiors are admitted only after every split building on the tile
  has placed its exteriors, one group at a time, from what the exteriors leave
  of the large allowance and of the tile's reads, meshes and draws. 165 of the
  280 interiors are drawn; 115 are capped because the large allowance is spent
  (#644).
- **Set doodads.** The set doodads standing in Stormwind are placed by the tile
  they stand in. A doodad inside an interior group's box belongs to the tile
  owning that group, which places it only while it draws the group. Doodads of
  interiors that are not drawn are left out. Outdoor set doodads are placed
  before interior ones, so an interior doodad never takes a slot an outdoor one
  had (#643, #644).
- **Sizing.** When a border building is sized alone, its cutout- and
  blend-only parts do not count toward the decision to split it; they are
  capped against the material budget when resolved. It fixes a case in the new
  rule (#643) where a building with 90,000 opaque and 45,000 cutout-only
  vertices would have been split and lost its interiors; no released build was
  affected (#644).

## Counting and portal ranges

- **Capped split buildings.** When a building drawn by group does not fit a
  tile, each of its groups still lands in exactly one count, so its map-wide
  totals add up: groups already settled keep theirs, owned interiors count as
  `GROUP_INTERIOR_CAPPED`, and owned exteriors count as `GROUP_CAPPED`, a new
  count. Nothing else the capped share read is counted. A capped building of
  the tile's own still has its groups uncounted, as before (#645).
- **Portal ranges measured.** Each group's real portal range (from its MOGP
  header) was compared with the range recovered from the root's MOPR. In the
  5x5 prep areas around Stormwind, Orgrimmar and Ironforge, 108 of 109 roots
  and 974 of 975 groups are exact. Stormwind is exact on 288 of its 289 groups.
  The one inexact group, Stormwind's group 252, also gets a one-sided reference
  that lies between its span and group 251's, which errs toward drawing more.
  The rule pairs exactly the 977 portals referenced once from each side, with no
  false pair. 12 portals, all in Stormwind, are referenced from one side only
  (#644, #645).

## Interior lighting

- **Lit from their vertex colours.** Interior groups, such as caves and
  building interiors, were lit by the World's sun like exteriors, so caves
  looked flat and too bright. An interior group with vertex colours (MOCV) is
  now lit by its raw vertex colours alone, with neither the sun nor the World's
  ambient. The building's ambient colour (MOHD) is not added, because the
  client is understood to have already folded it into the stored colours. An
  interior group without vertex colours keeps the World light, so it never
  draws black. Exteriors are drawn exactly as before (#646).
- **Unlit and fog.** Unlit parts still draw at full intensity, and fog is
  unchanged. `-Dvimi.world.wmoVertexColours=true` still affects only exteriors;
  interiors use their colours by default (#646).
- **Thunder Bluff.** On tiles 33–34 by 31–32 on map 1, 9, 5, 15 and 12
  interior groups (on 33,31, 33,32, 34,31 and 34,32) are lit from their vertex
  colours, and the Spirit Rise cave's 3 drawn interior groups all have them.
  Over 12 views from inside the cave,
  mean frame brightness ranged from 41 to 93 with the sun and from 15 to 70
  with raw vertex colours. Of the 21 distinct interior groups lit on these
  tiles, none has most of its vertices near black (#646).

## Storage

Library storage is unchanged: no schema, user version or table changed since
alpha.33, and no saved binding stamp changed, so nothing is rebuilt.

The tile objects file went to version 8, whose range classes may carry the new
interior light flag; versions 3 to 7 are refused. Those files are written per
session, so no saved objects tile outlives the change (#646). Its per-tile
ceiling went from 28 to 33 MiB with the large allowance (#643). The WMO root
reader now also keeps each group's MOGI box; the root facts revision stays
`wmo17-facts-v2` (#643).

## Measurement and tests

- In prep mode the probe prints one `PROBE tile` line per tile: its building
  vertices and indices, every pool, its building placements, roots drawn,
  capped and drawn by group, groups drawn and groups another tile draws, and
  with `-Pprobe.root=<FileDataID>` whether that root is drawn (#643).
- With stage timings on, the stream controller counts objects sets refused for
  the objects budget, `parent.objects.budgetRefused` (#643).
- New tests cover drawing by group: the owner rule with rotated and scaled
  placements and border points, each group drawn by exactly one of two
  neighbouring tiles, fitting buildings never split, the large allowance, a
  tile owning no group, a second placement capped without failing the tile, and
  a busy tile where everything else draws first (#643).
- New tests cover the root-built portal set: ranges recovered from paired
  portals, one-sided references inside and between spans, refused interleaved
  or unpaired references, both tiles carrying the identical set, walks crossing
  from one tile's groups to the other's, interiors capped by the allowance, two
  split buildings on one tile, instance maps, set doodad order and the sizing
  fix (#644).
- New tests cover interior-only shares, which need a free building slot, and a
  capped split building counting every group once (#645).
- New tests cover interior lighting: interiors carrying their raw vertex
  colours and the flag, a group flagged both exterior and interior lit as
  interior, interiors without vertex colours carrying neither, exteriors
  unchanged, and the version 8 objects file. The material-class GPU proof gains
  an interior-light quad whose pixel is texel times vertex colour, the same with
  vertex colours on or off, a changed ambient, or the sun shining straight at
  it (#646).

## Known limits

- **Interiors in cities are partial.** In the big cities most interior groups
  are read and then capped by the building geometry budget the exteriors
  leave, and counted as `GROUP_INTERIOR_CAPPED`. Undercity's exteriors already
  use 273,669 of its 294,912 building indices. Raising that budget is a
  separate decision. On one Undercity tile, roots whose portal set was dropped
  draw unculled, with only the few interior groups that fit (#641).
- **115 Stormwind interiors capped.** 115 of Stormwind's 280 interior groups do
  not fit what its exteriors leave of the large allowance, mostly on 48,30 and
  47,30, 47,31 and 48,31; 48,30 uses 131,064 of the allowance's 131,072
  vertices. A separate interior allowance would bring them in, at more GPU
  memory per owning tile (#644).
- **Set doodads inside interiors are not portal-culled.** Set doodads inside
  Stormwind's drawn interiors draw whenever their placement is in view, like
  every building's set doodads (#644).
- **Each owning tile walks the whole set.** That is up to 6 walks of 289 groups
  per frame for Stormwind (#644).
- **A second placement of a split building.** A building is decided once per
  tile by its largest placement. A second placement of a building drawn by
  group on the same tile is capped (#643).
- **Instance maps.** On instance maps, a building over the tile's remaining
  group reads is still capped before it is sized, so it is never drawn by
  group (#643).
- **Identical placement records.** The owner rule assumes every tile that
  lists a placement holds an identical MODF record for it; tiles whose records
  differed would pick different owners (#643).
- **Interior lighting.** Interiors are lit from their raw vertex colours, and
  the client's exact formula is not pinned (#474): the alpha term of the
  client's colour adjustment is not applied, and MOHD flags 0x2 and 0x8 are not
  honoured. If the client does add some ambient, interiors can look darker than
  in the client; the two darkest seen in Thunder Bluff are root 113750 group 1
  and root 113146 group 2. Doorway (trans) batches get full interior light,
  with no blend to the sun. A group flagged both exterior and interior is lit as
  interior, where the client may light it as outdoor. There is no sky and ground
  split of the ambient, and the building's own lights are not read. Set doodads
  marked to use interior light (MODD 0x2) are still lit by the sun (#383, #293,
  #646).
- **Exterior image levels.** The reserve for interior images can lower an
  exterior image's level slightly, by at most the smallest level of each
  interior-only image (#641).
- **No switch for interiors.** Interiors are always drawn; no setting turns
  off only interiors. `-Dvimi.world.exteriors=false` still turns off all
  buildings. Only the probe can measure exteriors without interiors (#641).
- **No World creatures on Anniversary.** There is no reviewed source of
  creature spawns for build 2.5.6.70577, so `-Dvimi.world.creatures=true`
  shows no creatures there.
- **Humanoid NPC appearances on Anniversary.** The tables that describe
  humanoid NPC appearances have not been reviewed for that build.
- **Sky rows skipped on Anniversary.** 12 LightData rows are skipped because
  their colour values have a top byte that is set, such as `0xFF242141`, and
  what that byte means on this build is not established. In 10 rows, from two
  parameter sets, the sky colours are unreadable and the whole row is skipped.
  In 2 rows, from two other parameter sets, only the direct and ambient light
  are dropped and the sky and fog are kept (#634).
- **Other layouts.** Only the Anniversary Map, LightParams and LightData
  layouts added in alpha.32 are reviewed. Other classic layouts are refused
  until they are seen and reviewed (#632, #634).

  The Metal shaders are built, and nothing new was run on macOS hardware.
- **Creatures still in the rest pose.** In the previews, billboard bones with
  child bones or rotation keys, members not rigidly bound, lock-X cards and a
  few parent-inheritance flags still refuse the Stand. In the World, 3 models
  with ignore-parent flags and the two models above the bone limit stay in the
  rest pose. Models whose Stand records no bone keys show their rest pose
  (#384).
- **Creatures not drawn in the World.** On Classic Era, 70 of the 1,051 sampled
  census models still have no surface the World can draw, and 2 have
  visibility unresolved. The remaining refusals include 19 character race
  displays with no table naming their skin, which need character composition
  (#385); 3 displays with an empty object skin slot; and 3 whose texture is not
  stored in the measured local copy. Two external-skeleton models are still
  not drawn because of other blockers (#636, #639).
- **Glow and blended parts in the World.** Colour tracks are not applied as
  tints or alpha, so a blended part can draw more opaque than in the client.
  Glows are drawn unlit, so glow batches not marked unlit draw brighter at
  night than in the client. Blended parts sort per part within a creature, so
  overlapping parts can sort wrongly from some angles. A creature shown in its
  rest pose draws its camera-facing glow and blended quads fixed. Fading
  weights are taken at time 0 of Stand, so a glow that pulses or fades during
  Stand stays at that value. On models whose Stand plays from an external
  skeleton, a keyed weight is decided only when every keyed slice starts full,
  the model has no sequences or global sequences of its own, and the track
  uses step or linear keys on sequence time (no global clock); the others are
  still left out, as are
  fading weights on creatures in the rest pose. Weight tracks are not read from
  `.anim` files or a parent skeleton (#361, #623, #625, #628, #636).
- **Bone files** are not applied for character displays, and `.anim` files and
  parent skeletons are not read (#384).
- **Sun direction.** The light's direction is still fixed. The light tables
  record colours, not a direction, and the client's sun path is not pinned yet
  (#177).
- **Water depth.** The shallow-to-deep mix reads the depth byte linearly; the
  client's exact curve and water textures are not used yet (#594).
- **View distance.** Near stays the default; whether Far becomes the default is
  not decided (#173).
- **Opt-in features.** These are Java system properties for testing, not
  settings in the app yet:
  - splat blending: `-Dvimi.world.splat=true`;
  - the recorded sky, fog, light and water light: `-Dvimi.world.sky=recorded`,
    with `-Dvimi.world.sky.time=HH:MM` to pin a time;
  - creatures: `-Dvimi.world.creatures=true`;
  - WMO vertex colours on exteriors: `-Dvimi.world.wmoVertexColours=true`
    (interiors use theirs by default);
  - high object texture detail: `-Dvimi.world.objectTextures=high`;
  - native presentation into a child window, on Windows only:
    `-Dvimi.world.nativePresent=true`.

  `-Dvimi.world.viewDistance=far` still forces the Far view distance. Terrain
  lighting is on and can be turned off with
  `-Dvimi.world.terrainLighting=false`.
