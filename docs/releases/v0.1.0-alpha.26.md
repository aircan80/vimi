# VibeMiner v0.1.0-alpha.26

GPU terrain now draws on Windows. On Windows the World Explorer's inline GPU
renderer uses Direct3D 11 by default, and with GPU terrain on it showed only the
sky. The instanced terrain shaders bound their per-instance data to the wrong
Direct3D 11 input slots, so every terrain triangle collapsed and nothing was
drawn, with no error. The shaders now use the slots the pinned bgfx expects,
and a test checks the input signature of every packaged Direct3D 11 instanced
shader so this cannot silently return. On an NVIDIA RTX 5090 under Windows 11,
Zephras Isle drew terrain, river and cliffs with all nine tiles textured. For
comparing renderers on one machine, `-Dvimi.gpu.backend=vulkan|d3d11|metal|default`
or the `VIMI_GPU_BACKEND` environment variable picks the backend.

The World viewer no longer closes while you walk. When the camera moves on,
work for tiles it leaves is cancelled. When that cancellation happened inside a
file read, Java wrapped it in several layers, and the World code mistook the
wrapped cancellation for a real failure: the viewer froze on its last frame
with "World viewer failed", within about half a minute to two minutes of
walking. A chain made only of plain cancellations is now treated as the
routine stop it is; anything else in the chain is still a real failure. The
same fault in terrain texture loading, where a cancelled texture job could
leave texture loading broken until restart, and in the stream controller is
fixed too. Water validation also no longer looks up file names it does not
need. This was found on Windows but was not specific to it.

World failures can now be diagnosed. When the World helper process ends
abnormally, the application log records its exit code, whether it closed
cleanly, the failure with its causes, and the last 40 lines of its error
output. Failures of buildings, creatures and water on a tile are logged too,
at most once a minute per part with a count of the ones skipped, and the
window shows a short reason instead of a generic message. Before anything is
logged or shown, local file paths, the home directory, the user name and the
host name are replaced with `<path>` or `<redacted>`. Redaction errs on the
side of removing too much: text after a path on the same line is lost.
Relative folder paths, such as those inside a game folder, are not yet
redacted. Logs stay on your computer.

Outdoor buildings now include see-through materials and doodads. Cutout
materials, such as fences and foliage, are drawn with an alpha test, and
blended ones, such as glass, are drawn after water from far to near. Doodads,
the small models placed on terrain tiles and in each building's doodad set,
are drawn in their rest pose with their first texture. Only doodads that stand
upright and turn about the vertical axis are drawn; tilted ones and doodads
with flags whose meaning is not yet confirmed are counted, not drawn, and on
real Azeroth tiles that is most of them. The opaque surfaces of buildings are
decided first, exactly as in alpha.25, and see-through surfaces and doodads
have their own budgets. A see-through texture that cannot be read, a
malformed doodad list or a doodad model that fails to load omits only itself,
never the building. The status line now says what was not drawn, for example
"not drawn: 3 buildings, 41 doodads (12 tilted), 9 surfaces (2 unreadable)".
The worst-case GPU memory for objects rose from about 79 MB to about 150 MB.
Doodads and see-through materials have not yet been seen on real data, because
their models and textures were not stored locally, and only Linux Vulkan was
run.

World Explorer can draw creatures at NPC spawns. This is off by default; start
with `-Dvimi.world.creatures=true` (outdoor buildings must also be on). A
spawn is drawn only when its creature model was chosen exactly, it lies on a
tile, its display needs no character appearance or geoset choice, and its
model has an opaque textured part. Models stand in their rest pose without
animation and all face north, because the spawn data records no facing. Each
tile draws at most eight creature models and 32 placements, and buildings get
room first. A creature problem never costs a tile its buildings or terrain. The
status line counts drawn creatures and undrawn spawns by reason. This has not
been checked on real data or a GPU, which is why it is off by default.

Undead male race models play their Stand idle animation. A race model plays
Stand only when every link from the race row to the model is recorded data,
and the model has no separate skeleton or bone files. The Idle toggle appears
only when the animation matches the model on screen; otherwise the preview
says why. On one Forever 1.60.1 build, the Undead male Stand animation moved
44,939 vertices with 226 bones from the bind pose into the hunched Undead
stance. Worgen and 36 other race models pass every check but could not be
confirmed, because their mesh files were not stored locally; they show the
missing file. Models with more than 256 bones, such as the Algarian
Stormrider, stay unsupported. Mount idle animations may now loop on longer
clocks, which only admits more mounts.

Building a library's common tables is faster again. Up to eight table checks
and four table builds now run at once, with results still taken in the
original order, and each table file is read once instead of twice. On one
Forever build with 1.25 million files and 1,270 tables, building the common
tables from scratch fell from about 123 s to 82 s, and checking already built
tables from about 6.7 s to 1.9 s. Every table ended in the same state, byte
for byte. If preparation is cancelled, a few tables past the stopping point may
already be saved; they are complete and are reused next time.
