# VibeMiner v0.1.0-alpha.23

Client hotfix caches can now be applied to table data. In Preparation, import a
build-matched client hotfix cache (XFTH v9 `DBCache.bin`). Vimi keeps a private,
immutable copy and reopens the workspace with it as an overlay. Ordinary table
reads then include hotfix-added and hotfix-replaced records, and they drop
records the hotfix explicitly deletes. Records the overlay cannot resolve stay
marked as protected or unknown instead of silently falling back to stale base
data. Encryption keys delivered by the hotfix cache join normal key loading, so
tables encrypted with a hotfix-only key become readable. Talent details show
where each record came from. "Use base data" detaches the cache but keeps the
imported copies; docs/data-flow-inventory.md describes storage and privacy.

Prepared-only comparison and physical native evidence are unchanged and still
describe the base build. The overlay policy is conservative and does not claim
full parity with the game client's hotfix handling. The specific build 70707
cache and talent examples reported against this feature were not available
for verification. Forever TraitTree talents (#164) and automatic hotfix
refresh (#168) are still in progress.

Windows packaging works again. The Checkstyle worker process now gets a 1 GiB
heap instead of Gradle's 512 MiB default. Alpha.22 did not publish because
the Windows package ran out of memory there.

World Explorer can show declared NPC spawn points. A new NPC spawns footer
toggle, off by default, draws markers from the prepared Polestar spawn table,
which records world positions on the client map. Points without a recorded
height are counted but not placed on a guessed floor. The status line names the
source client build and reports in-view, in-range and height-less counts.
Markers have no depth test, phase is unknown, and creature models are not yet
drawn at these points. Area-percentage and interaction-observation sources are
deliberately not used as spawn positions.

World Explorer has a walk mode. Walk on terrain (F) keeps the camera 2 yards
above the rendered terrain surface at 7 yards per second, doubled with Shift.
It lifts at once on rising ground and eases down on falling ground. Over holes,
unloaded tiles or terrain whose mesh layout is not recognised, walk holds
altitude and the footer says so. There is no collision or floor inference.
Smooth motion, on by default, eases camera velocity; with it off, flight moves
as before. Speeds and eye height are explorer conveniences, not client parity.

The build can now compile the isolated global-model candidate shaders for DX11
on Windows when explicitly requested. This is build groundwork only: the
instance viewer is not enabled and the shipped shader set is unchanged.

World Explorer's GPU terrain now shows static water as a diagnostic surface.
Constant-height lakes and seas from the tile's liquid data draw as a flat,
untextured, translucent teal layer that follows the shoreline and is hidden by
nearer terrain. Moving water, waves, textures and non-flat liquid layers are not
drawn yet. Water is optional: tiles whose water can't be qualified keep their
terrain, and `-Dvimi.world.water=false` turns it off. The status line reports
how many tiles show water.

Alpha.21 and alpha.22 were tagged but never published, so this prerelease also
carries everything from alpha.22, repeated below.

World Explorer now keeps one GPU renderer running as nearby terrain changes.
Camera updates continue while terrain and textures prepare off the UI thread.
New tiles arrive with their prepared texture coverage instead of rebuilding the
whole viewport for each arrival. Loading favors neighbors ahead of the camera. Memory-pressure retries wait for a
relevant resource change or a bounded timer instead of churning on camera frames.

The viewer retains the previous useful image while terrain in the viewing
direction is pending, with visible loading feedback. When necessary, that image
is explicitly marked as the previous view so obsolete source resources can
retire and loading can continue. GPU/software switching, hiding, reopening and
closing wait for the previous renderer's actual retirement.

Independent lifecycle and cancellation regressions pass. An actual Linux Vulkan
movement diagnostic reaches nine textured tiles, including four with partial
coverage, and closes with zero atlas claims. This is not a sustained FPS benchmark.
No acquired game artwork is included in the release.

Terrain still uses the BASIC texture recipe and the existing neighborhood and
viewport bounds. Larger view distance, improved material fidelity, cities,
doodads, water and global-model dungeon rendering remain in progress. Raw global
WDT source support is included as a foundation for instances. Partial or missing
texture coverage is still possible. Actual Metal/D3D runtime qualification remains
separate from cross-platform builds and package smoke checks.

Maps now becomes available when table preparation completes. Its tab no longer
keeps a Loading label merely because later background work is active.

Linux ARM64 package checks receive the verified JavaFX SDK native-library path.
Alpha.21 did not publish because that check lacked the path; this prerelease
includes its streaming improvements and the build correction.

Explorer turning, strafing and projection now agree with native geographic axes
and the minimap. This corrects the reflected lateral camera view that made the
minimap appear to turn the wrong way.

The Races preview exposes source-qualified Dwarf skin-color choices, with loading
feedback, cancellation and stale-result protection. It also admits the verified
Night Elf male/female static body and hair profile, with required base-texture
checks. These are static asset previews; unsupported surfaces remain explicit.
Undead appearance eligibility and broader character customization remain pending.

An open Maps view refreshes after source revisions. Failed World map catalog
loading now shows an unavailable/retry message instead of an endless placeholder.

Fix handmade BC3/DXT5 terrain textures rejected as DIFFUSE_PROFILE. The explicit
handmade profile now admits the reported colour2/alpha8/encoding7 tuple through
both decoding and streaming, while retaining full mip-chain validation. Decoder
cache identity changes so older generated results are not reused. Unsupported
handmade tuples now report their actual encoding and alpha fields.
