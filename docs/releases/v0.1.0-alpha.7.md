# VibeMiner v0.1.0-alpha.7

This prerelease extends Compare with one explicitly selected raw table. In Tables,
enter its FileDataID or prefill it from a selected inventory finding, then select
Compare readable rows locally. Choosing a table or result does not start work.
The normal Compare local data action still compares inventory.

Both endpoints must match product, locale, table identity, observed layout and the
reviewed definition/field policy. Schema compatibility is checked before either
input is sorted. Only existing prepared local graphs are read: missing graphs,
corrupt data or lost source segments do not trigger acquisition, repair or table
rebuilds. Prepared-local key bootstrap retains community-key fallback.

Findings compare verified recorded cells with explicit array positions, reference
IDs, exact text and finite float32 values. Row IDs use the full unsigned32 domain.
Invalid, protected, limited and missing issue-channel evidence remain distinct;
readable PARTIAL data contributes useful cells. Unverified/raw/narrowed columns
are listed as unassessed. Copy-record representation is interpretation evidence.
These are raw-cell findings, not gameplay conclusions.

Membership remains uncertified, so unmatched rows are observed-only rather than
proven additions/removals. Results are session-only and bounded. Capture, sorting,
retained inputs and results share one working-memory and scratch-file policy.
Cancellation and leaving Compare drain the pair and remove recognized scratch.

Validation includes 104 comparison component/adapter tests, 96 table component
tests and native integration fixtures. An authored real SQLite/pack graph proves
cached reuse with an unreadable original payload, missing-graph rejection,
unsigned maximum row ID, zero acquisition and no object writes. Independent
architecture and domain reviews approved the slice before native CI/publication.
#117 remains open for semantic areas, provider snapshots and later capabilities.
