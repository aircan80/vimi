# Persistent World native preparation checkpoint

This first production-core slice is not wired into GpuViewerMain, pipes, GUI or source factories. WorldStreamPackedTile.prepare consumes a decoded packet's heap owner on the bounded decoder worker, computes the existing native flat-color/altitude shade into absolute-native48-byte triangle instances, and allocates at most3MiB geometry plus1MiB optional atlas. No bgfx call occurs on that worker. Successful/failed preparation clears the decoded Payload's raw Tile/atlas references; retained futures keep metadata only. Array/buffer views remain synchronous trusted package borrows and cannot establish source authority.

Packed ownership transfers exactly once via take(). Closing its producer wrapper after transfer cannot free native inputs. The recipient Source owns direct buffers until the native upload's real make_ref_release callbacks drain. It is not a callback-safe free primitive: only that recipient may close the transferred Source after drain. The upcoming renderer owns this protocol; no arbitrary view can advertise packets or mutate source evidence.

The eight reviewed feasibility shader blobs are copied byte-identically into the new production shaders/world-stream namespace with identical source/manifest provenance and a separate verification helper. Existing24model/immutable-terrain/sky blobs are untouched. processResources/check verify both domains, and GpuRuntimeProbe now verifies/counts32actualpackagedblobs including the new8. No GPU initialization is implied by linkage/hash probe. Runtimequalification remains Linux Vulkan only until additional backend execution evidence exists.

Three authored worker fixtures prove native+X shade(44.28,71.34,41.82), preserved absolute coordinates, one-shot transfer, maximum4MiB direct ownership and cancellation consuming/clearing raw inputs. The preexisting10packet tests still pass with explicit Payload.close available. Full rendering-bgfx checks and both shader verification gates pass. This checkpoint does not claim a live persistent renderer, frame cadence or a whole-JVM/driver budget; fixed resources/readback/commit/nativeproof follow separately.

## Fixed renderer and owner checkpoint

`BgfxWorldStreamRenderer` owns ten fixed dynamic instance buffers (pinned runtime4MiB backing each), ten512²RGBA textures, one selector/sky VBO and the stream+existing-sky programs. Only the initializing native thread may begin/step/cancel/commit/draw. begin consumes one Packed Source; only one uploading or STAGED incoming lease exists. A slot cannot overwrite an active lease or reuse an old generation. Commit accepts only current active members plus the one newly staged lease, with at most9unique slots/filename coordinates and explicit source order. It exchanges metadata only between draw calls; no GPU neighborhood re-upload or context replacement occurs.

Each upload step enqueues at most two98,304-byte geometry references and one65,536-byte atlas strip, at most262,144bytes, checking a2ms target BETWEEN native calls. Driver calls cannot be preempted: the target is not a2ms hard time guarantee. At most48make_ref_release tickets exist. Callbacks carry a monotonic upload tag plus ticket, validate pointer range/issued/duplicate identity, update atomic scalar facts and invoke no IO/source/UI callback. Only the native owner frees Source buffers after real reference drain. For future controller integration, issuedReferences/releasedReferences expose bounded counts: reconcile newly issued before consuming release deltas, and before CANCEL/STAGED/COMMIT/credit changes. The existing pure WorldStreamState/controller must enforce offer transaction/credit/decoder rules; this renderer is not that runtime actor.

`WorldStreamNativeOwner` owns an explicit offscreen backend context with fallbackfalse, one-frame command latency, capability/hardware checks, fixed800×500BGRA color+D32F and three fixed BGRA readback textures/native destinations. Dimensions change only the view and cropped publication, never GPU allocations. One existing1.6MiB scratch crops/normalizes rows; no per-frame heap pixel clone exists in this child. The borrowed v2 frame mapping must match nonce/scope and be fresh; a fresh session/mapping is required for a successor context. The singleton guard rejects a second context before initialization. Close drains pending readback fences, destroys owned handles, calls real bgfx_shutdown, THEN releases remaining upload buffers and callback closure. The mapping is borrowed and remains caller-owned.

At most ONE draw/readback request may enter a bgfx frame; the three ring tickets span DIFFERENT native frames. Without that guard, bgfx's ordered view0draws followed by view1blits could associate all readbacks with the last draw. Each ticket captures actual camera/content/policy/dimensions at draw time. Publication drops old-policy/size or regressing content/camera completions, while allowing lagging monotonic camera frames during continuous input. A COMMIT with unchanged camera revision still schedules a new content frame. Reusing a camera revision with different controls refuses. Revision/sequence exhaustion refuses wrap.
