# Cold WMO structural codec checkpoint

This implements only the neutral view/codec part of the approved23ecedb/a4b9e12 cold annex design. It adds `BasicWmoData` in rendering-world and `GpuWorldWmoAnnex` in rendering-bgfx. No existing renderer, native owner, hot protocol, process launch, source facade, GUI or shader file changes. A view may be authored/forged and a decoded annex means only bounded structural presentation data; neither authenticates game sources. Positive source authority remains the private live WorldBasicWmo factory and the future trusted unadvertised writer integration.

The exact little-endian512-byte header/64-byte source/64-byte raw MOMT/16-byte batch/64-byte image/32-byte vertex/unsigned16-index layout is implemented as proposed. Actual base write/read `FileDigest` supplies whole serialized SHA/length; selected original tile fingerprint and exact shared origin are checked separately. Header/offset/count arithmetic precedes payload arrays; images are decoded from the packet one bounded image at a time with≤64KiB buffered file input, no annex-sized byte array. Canonical maximum1,594,400bytes is below the unchanged2MiB file ceiling. Unknown declared lengths remain null and are distinct from consumed lengths/source limits.

SHA256 covers every header/body byte except the checksum's own32-byte range, and each image has its own SHA. Every reserved field, recipe value, canonical section/pixel offset, fixed role/source limit, raw material-stage domain, batch partition, image order/alpha/dimensions, index/finite/unit-normal/UV/coordinate condition, computed matrix literal and complete EOF is checked. Generic source IDs/keys remain descriptive; the codec does not read/acquire game files or certify causal ancestry. Reader returns no uploadable/decoded data on a checksum or semantic failure. CREATE_NEW writer failures delete only the newly owned partial file; preexisting destinations stay untouched.

The primitive arrays actually retained by maximum Decoded are three mesh float arrays totaling16384bytes, int32 CPU indices6144bytes, and six RGBA byte arrays totaling1572864bytes:1,595,392payload bytes. IPC/GPU indices remain unsigned16, so serialized mesh remains19456bytes; queued/native mesh is21504bytes since #375 added a 4-byte vertex colour to the GPU vertex. Image constructor wraps a private decoded array in a read-only view without a second complete RGBA snapshot. Sources/materials/image descriptors and transient hashes/header remain small named metadata owners; file buffering is65536bytes and pixel hashing scans read-only buffers without a whole-packet/pixel clone. This is a logical representation count, not an RSS/native/GPU queue measurement. The unchanged proposed additional-child6,175,744byte ledger still requires native upload/retirement proof before rendering; no native overlap/capacity claim is made here.

One explicit structural numeric refusal supplements the design: huge finite raw placement/local floats can cancel to bounded world positions in double while their actual float model multiplication produces a different position far beyond the world bound. Before accepting a view/Decoded, evaluate the quantized float model-to-origin operation and require finite relative positions within±2×MAX_COORDINATE. An authored example has double world(-772240.578125,-673776.265625) but float relativeX=-8388608; it must decline. Ordinary shared-origin/cardinal/scale oracles retain exact double construction and explicit coefficient quantization tolerances. This does not claim general pixel parity or a stricter source budget.

The CPU recipe oracle pins BASIC fragment depth/fog and lighting only: unit vertex normals can interpolate to zero, so squared length≤1e-12 gives ambient-only1/3 with diffuse0; otherwise normalize. No face-normal substitution. The WMO fragment rule uses depth0.5..2200 inclusive, its own per-fragment fog, byte-floor output and explicit sky bytes. Legacy terrain keeps its flat maximum-original-triangle rule. `modelToOrigin` uses double origin subtraction before one float coefficient cast and independent `u_wmo*` is reserved for the later native pass. No shader is implemented or validated by these CPU tests.

## Validation and limits

`JAVA_HOME=/usr/lib/jvm/java-25-openjdk ./gradlew :rendering-world:check :rendering-bgfx:check :concepts-world:check` passes formatting, Checkstyle, unit suites, existing shader verification/compiler-helper tests and the existing runtime capability probe. The probe explicitly does not initialize a GPU. Ten authored codec tests cover the exact maximum packet/CPU payload count, immutable decoded storage, actual nine-tile base swaps with the same selected tile AND origin, many independently rehashed malformed header/body fields, counts/truncation/trailing bytes/checksums, canceled partial write/read/preexisting-file ownership, all cardinal headings/three positive scales/shared-origin asymmetric camera arithmetic, double-vs-float catastrophic cancellation, zero-normal ambient and the named fragment clipping/fog/floor rule. Binary bodies are authored fixtures, no game assets.

Causal controls independently remove whole-base SHA pairing, canonical header offsets and quantized float-coordinate validation. Each corresponding test fails with that guard removed; production is restored and all three module checks rerun. Private logs are `/tmp/vimi-wmo-annex-negative-{base-sha,offset,float-pose}.log` and `/tmp/vimi-wmo-annex-restored-check.log`.

Still separate: live selected-build factory witness after observed-row Map admission, trusted source callback→unadvertised packet adapter, independent codec review, native WMO shaders/draw pass and actual same-frame reversed-depth/camera/texture proof with measured owner overlap. No visible building or instance release is claimed by this checkpoint.
